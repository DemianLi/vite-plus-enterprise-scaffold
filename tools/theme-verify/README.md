# @org/theme-verify

設計系統接縫的驗收（HANDOFF #24）。回答的是**一句產品要求能不能兌現**：

> 公司會有一套基礎的 UI 版型和互動方式，但是各團隊可以依不同案件需求
> 更換配色或 component 形狀或互動方式。 —— C62

**這支工具守前兩條軸，第三條不在這裡 —— 而且不該在這裡。**
「互動方式」換不了代幣，它是靠組合（slot／emit）換的，所以守它的是
`tools/api-surface`：元件的 slot 與 emit 必須宣告，宣告改了會漂移
（2026-08-17 起，見 C67）。**這支工具綠燈的意思是「配色與形狀實測可換」，
不是「設計系統可換」。**

## 三段，缺一不可

```bash
node tools/theme-verify/src/cli.ts      # 三段一起跑，約 0.3 秒
```

| 段       | 驗什麼                                                     | 少了它會怎樣                                      |
| -------- | ---------------------------------------------------------- | ------------------------------------------------- |
| **靜態** | 元件**與切片／應用**裡不准出現原始顏色（內建色階、色票層） | 元件寫死 `bg-gray-50`，代幣接得再好也換不到那一格 |
| **引用** | 產物裡不准有指向不存在代幣的 `var()`                       | 代幣改名時，使用端留在原地而**沒有任何東西會紅**  |
| **建置** | 同一份 fixture 建兩次，一次帶覆寫一次不帶                  | 「代幣寫在那裡」不等於「覆寫會生效」              |

轉換前的基線是 **15 處原始顏色**（`UiButton` 12、`UiDialog` 3），現在是 0。

> ⚠️ HANDOFF #24 記的是「16 處顏色宣告」，兩個數字都對：那 16 處裡有 1 處
> 用括號語法直接引用代幣，當時已經是語意層，不算違規。**15 ＝ 16 − 1。**

### 靜態那一段在 2026-08-17 從供應端擴到消費端

元件一行原始顏色都沒有，**不代表各案換得掉配色** —— 切片自己在頁面上寫
`text-gray-900`，那一格就永遠是灰的。乾跑撞到 **4 處真陽性、0 偽陽性**：

| 位置                                   | 寫死的           |
| -------------------------------------- | ---------------- |
| `features/order/…/OrderList.vue`       | `text-gray-900`  |
| `features/shipment/…/ShipmentList.vue` | `text-gray-900`  |
| `apps/console/src/App.vue`（略過導覽） | `focus:bg-white` |
| **`tools/slice-gen/src/files.ts`**     | `text-gray-900`  |

⚠️ **第四處是前三處的來源。** 產生器模板寫死顏色 ＝ 每個新切片天生帶著
一個換不掉的顏色，與 D15 落地當下「模板忘了 `@org/ui`」同一個形狀（C41）。
產生器那一側由 `slice-gen` 的測試釘住，用的是**同一支** `findPaletteUsage`
（本 package 因此開了一個 `./palette` 出口）—— 各持一份的話，
這裡收緊而模板沒跟上，兩邊測試會一起全綠。

⚠️ 這與下面「這支工具不驗什麼」那一節**不衝突**：那裡講的是不驗
`apps/console/src/styles.css` 的 `@theme` 覆寫**值**（那是刻意留給各案的
擴充點），這裡擋的是模板裡**繞過代幣層**寫死顏色。前者是用擴充點，
後者是不用。

### 「引用」這一段是 2026-08-17 補的，補的是它自己漏掉的東西

前兩段上線的那個 PR，同時把 `--color-muted` 改名成 `--color-fg-muted`，
而 `features/order`、`features/shipment` 與 `tools/slice-gen` 的模板共 **6 處**
引用留在原地。產物裡因此有一條

```css
.text-\(--color-muted\) {
  color: var(--color-muted);
}
```

指向一個不存在的名字 —— 瀏覽器會讓整條宣告失效（`color` 的結果是安靜地繼承
父層），而那個 PR 的閘門**全綠**：靜態段只掃 `platform/ui/src/components`，
看不見設計系統的**使用端**。

這一段掃得到全 repo，是因為 `platform/ui` 的 `@source` 是一條從 repo 根往下的
glob：fixture 建置會把 `features/`、甚至 `tools/` 裡的模板字串一起編進來。

⚠️ **它看不到的那一半要寫清楚**：

| 寫法                          | 代幣不存在時 Tailwind 會…  | 這一段 |
| ----------------------------- | -------------------------- | ------ |
| `text-(--沒有的代幣)`         | 照樣編出規則，`var()` 懸空 | 抓得到 |
| `text-沒有的代幣`（工具類名） | **什麼都不產生**           | 抓不到 |

也就是改用正規工具類名之後，同一個錯誤反而更安靜。產生器模板那一側因此另有
一條原始碼層的耦合（`tools/slice-gen/tests/contract-alignment.test.ts`），
切片那一側目前**沒有**，記在 HANDOFF #24。

## 為什麼一定要真的建置

因為 Tailwind 的失敗模式是**建置成功、CSS 甚至變大，但裡面什麼都沒有**
（`@source` 掃不到來源時，見 `platform/ui/tests/styles.test.ts` 的檔頭）。
一支只 grep `styles.css` 有沒有寫 `@theme` 的測試，量的是「有沒有寫」。

而比對的是**解析後**的值，不是宣告文字。代幣分兩層：

```css
--color-brand-600: oklch(…); /* 色票 */
--color-accent: var(--color-brand-600); /* 語意 */
```

app 端覆寫色票時，`--color-accent` 的**宣告文字一個字都不會變**。
只比對文字的話，最該驗的那一格永遠通過。

## 九條斷言，八條實測會紅

| 斷言                                        | 破壞方式                                  | 結果 |
| ------------------------------------------- | ----------------------------------------- | ---- |
| 元件零原始顏色                              | 把一個 variant 改回 `hover:bg-gray-50`    | 紅   |
| 產物零懸空引用                              | 把代幣改名、使用端不動（2026-08-17 實況） | 紅   |
| 產物真的解析得到代幣宣告                    | 讀到 0 格宣告時直接紅，不是「零違規」     | 紅   |
| 被覆寫的代幣，兩版解析值不同                | 把覆寫值設成與預設相同                    | 紅   |
| 語意層跟著色票走                            | 把 `--color-accent` 改成直接寫值          | 紅   |
| fixture 不得被掏空                          | 刪掉 `override.css` 的 `@theme`           | 紅   |
| 至少一條元件用到的 utility 引用被覆寫的代幣 | 元件全面改用別的代幣                      | 紅   |
| 只寫在 `.ts` 裡的類別編得出來               | 清空 `fixtures/probe.ts`                  | 紅   |
| 覆寫零附帶影響                              | ——（要破壞它得改 Tailwind 本身）          | 未測 |

「產物零懸空引用」那一條的實測還包含一個死角測試：**只**把
`tools/slice-gen` 的模板改壞（兩個切片都是好的）也會紅 —— 產生器模板住在
`.ts` 裡，所以它落在 `@source` 的範圍內。

## fixture 為什麼不是 `apps/console` 那一份

`apps/console/src/styles.css` 也有一份真的覆寫，但那是**給人看的示範**，
各案會改它。閘門盯著它的話，換一個顏色就會紅，然後閘門會被放寬
（C41：會誤報的閘門第一天就會被加例外，而例外永遠不會拿掉）。

所以 `fixtures/` 底下自己有一份，值刻意選得很醜（洋紅、2rem 圓角）——
一個「看起來合理」的覆寫值，在比對失敗時分不出是覆寫沒生效還是預設值本來就長這樣。

## ⚠️ 這支工具自己踩過的兩個坑

**一、量 X 的工具自己成了 X 的來源 —— 而且發生了三次。**

第一版把要檢查的選擇器寫死在 `cli.ts`：`[".border-line", ".bg-accent", …]`。
`@source` 掃 `.ts`，**而 Tailwind 連註解一起掃** —— 於是那幾條規則被
這支工具自己的原始碼餵活了。實測：把元件裡的用法整條刪掉，檢查照樣全綠。

第二次更難看：改寫時留下一句「不要把選擇器寫死在這裡」的**警告**，
而那句警告裡就寫著那個選擇器。警告的那句話讓它警告的事情發生了。
候選因此改成先用 `platform/ui/src/components/*.vue` 的實際用法濾一遍
（`palette.ts` 的 `usedClassNames`，會剔除註解行）。

第三次是「引用」這一段抓到的，而且是在**同一份原始碼**裡：`css.ts` 與
`palette.ts` 的檔頭都寫著「第一版的 grep 認不得括號語法」，句子裡把那個
utility 完整寫了出來。Tailwind 照樣把它編成一條規則，指向一個叫 `--var`
的變數 —— 一條沒有人要、指向不存在名字的 CSS，一路進到**每一支 app 的產物**。

第四次在同一輪裡：`tools/slice-gen` 那條新測試要一個「不存在的代幣」當反例，
寫成字面值之後 Tailwind 照樣編出來，**這一段當場抓到了驗證它的那條測試**。

> 四次之後的規律：**在這個 repo 裡，`.ts` 的字串與註解就是 CSS 的來源。**
> 「這只是註解／只是測試資料」在 Tailwind v4 底下不成立。所以說明這個坑的
> 那兩處只寫括號、不補變數名，測試裡的反例則拆成變數再組回去 ——
> 並在旁邊寫明為什麼句子長得這麼彆扭，否則下一個人會把它「順」回去。

**二、用來量代幣化的偵測器，第一版看不見代幣。**

#24 第一次量顏色數量時寫的 grep 認不得 Tailwind v4 那個把自訂屬性直接放進
括號的語法 —— **它漏掉的正好是唯一被正確代幣化的那一類**，於是數字連錯兩次。

所以 `palette.ts` 的判準倒過來寫：**列舉違規的形狀**，不列舉合法的形狀。
漏列一個違規只會少擋一次；漏列一個合法形狀會擋掉正確的程式碼，
然後有人把整條規則關掉。

## 為什麼在 Tier 1 而不是 Tier 2

與無障礙同一個理由。Tier 2 的三條規則（不快取、不過濾、要有時間觸發）
只為了一件事：安全掃描的結果會隨時間失效。**「各案換得掉配色」不會** ——
沒有新公布的 CVE 會讓一個代幣變成換不掉。
