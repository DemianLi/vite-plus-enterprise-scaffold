# `.vue` 的複雜度盲區有多大 —— 而生的行數量到的是註解密度

> ⚠️ **量測基準 `2846949`**（2026-08-30）。這份稿子是**凍結的**，
> 沒有任何機制在守它過不過期（`SCOPE.md` 的 `reports/` 那一列）。
>
> ⚠️ **這是觀察，不是判準。** 不得拿來論證任何東西的准入或增減閘門（C137 §一）。
> 產生每一個數字的腳本在 [`rigs/vue-blindspot.py`](rigs/vue-blindspot.py)，
> 可以再問一次。

## 問的是什麼

`vite.config.ts` 的 C119 註解自己寫著：

> ⚠️ `<script setup>` 的 module 層在上面四條裡**一行都看不見**…
> 表上乾淨是因為量不到，不是因為程式碼乾淨

而 C120 §一 指定了門檻之前要先答的那個問題：**「元件的邏輯有相當一部分在
`template` 裡」**這件事成不成立 —— 不是先答一個數字。

這份稿子答那兩個。

## ⚠️ 主要發現：生的行數把盲區放大了 2.8 倍

|                                        | 生的非空行 | **扣掉註解**              |
| -------------------------------------- | ---------- | ------------------------- |
| 全部 31 個 `.vue` 的 `<script setup>`  | 2,403      | **864**（註解佔 **65%**） |
| 其中「四條規則一行都看不見」的 23 個檔 | 1,716      | **603**                   |

**極端的例子**：`UiDropdownMenu.vue` 的 `<script setup>` 有 **269** 非空行，
其中 **210 行是註解（78%）**，真正的程式碼 **59 行**。
`UiSkeleton.vue` 更誇張：102 行 → **9 行**。

⚠️⚠️ **所以「盲區 2,403 行」這個講法是錯的，而錯的方向會讓人去設錯的門檻。**
`vite.config.ts` 自己就寫過這條線的註解密度遠高於一般專案 ——
**對 `<script setup>` 設一個行數門檻，今天量到的主要是註解密度。**

（設定檔註解裡引 #129 的那組數字（24 個檔／1,992 行）**今天也已經過期** ——
實測是 31 個檔／2,403 行。）

## 盲區的真實大小

23 個零函式的檔，扣掉註解之後：

| 統計   | 值                              |
| ------ | ------------------------------- |
| 合計   | **603** 行                      |
| 中位數 | **19** 行                       |
| p90    | 51 行                           |
| 最大   | **80** 行（`UiDatePicker.vue`） |

**平均一個檔 26 行。** 這不是一片沒人看得見的沼澤，是 23 個小檔。

## C120 §一 那個先決問題的答案：**邏輯不在 `template` 裡**

|                            | 行數    |
| -------------------------- | ------- |
| `<script setup>`（扣註解） | **864** |
| `<template>`               | **487** |

**比值 1.8 倍** —— ⚠️ 而生的行數會算成 4.9 倍，又是同一個放大。
`template` 裡的邏輯標記（`v-if`／`v-for`／三元／插值裡的呼叫）全樹合計 **51 個**，
其中落在盲區那 23 個檔的只有 **13 個**。

**所以答案是否定的：邏輯確實在 `<script setup>`，而那正是四條規則看不到的地方。**
⚠️ 但接續的結論不是「所以要設行數門檻」—— 見上一節，那 603 行的中位數是 19。

## ⚠️ 同一塊程式碼被兩套機制同時漏掉

`platform/ui` 也是**突變測試**量不到的地方 —— C120 §一 記過「27 個 SFC
一個 mutant 都沒有」，而它與這裡是**同一個位置的第二次**（C119 已經這樣寫過）。

**這是這份稿子最該被記住的一句：一塊程式碼同時不在複雜度的射程裡、也不在
突變測試的射程裡，而兩張表上它都是乾淨的。**

## 量測台的五道對照組，以及它抓到的一次自己的錯

`rigs/vue-blindspot.py` 每跑一次都驗五條，任何一條不成立就 `assert` 中止：

| #   | 對照組                                      | 它接住什麼                                                 |
| --- | ------------------------------------------- | ---------------------------------------------------------- |
| 1   | 已知有函式的檔 `funcs > 0`                  | 函式偵測正則失效                                           |
| 2   | 母體不含 `/fixtures/`                       | 假元件灌進分母                                             |
| 3   | 母體數 == `git ls-files '*.vue'` 扣 fixture | 讀磁碟（C73／C98）                                         |
| 4   | 註解剝除的差值 > 0                          | ⚠️ 正則失效會回報「註解 0%」，**而那與真的沒註解長得一樣** |
| 5   | **每個檔 `props` <= 5**                     | ⚠️⚠️ 見下                                                  |

⚠️⚠️ **第 5 條抓到的是這支腳本自己。** 第一版用「這一行有沒有冒號」數 props，
於是 `UiDropdownMenu.vue` 的 `items: readonly { value; label; disabled; variant }[]`
把 4 個巢狀屬性也算進去，量到 **8** —— 而 `vue/max-props` 的門檻是 5，
**閘門卻是綠的**。

**那個矛盾就是抓到錯誤的地方**：不是規則沒開火，是計數器錯了。
**拿一道今天是綠的閘門當事實來源，是這份量測裡最便宜也最有效的一道對照組。**
